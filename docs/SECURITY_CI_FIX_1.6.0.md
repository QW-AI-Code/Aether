# Security audit / CI follow-up — app version unchanged

App versionName **1.6.0**, base versionCode **19**, PATCHLEVEL **1.6.0**.
This source-only correction does not change Android application code, config import,
UI, backends, signing identity or the Aether engine's 2.3.0 version.

## Why the screenshot had a checkmark and an error

The audit step used `continue-on-error: true`, so GitHub allowed the job to continue
although `cargo audit` returned 1 for security findings. The step's `set -uo pipefail`
did not disable GitHub's inherited Bash `-e`; the failing pipeline exited before
its status-handling and summary code ran. This was not an Android compiler error,
but the dependency finding was real, not a harmless formatting problem.

The screenshot's quinn-proto finding allows denial of service/panic from a remote
peer when unordered reads process empty STREAM frames. The default ordered-read
path is unaffected; this report does not claim a demonstrated exploit in Aether.
Authoritative advisory: https://rustsec.org/advisories/RUSTSEC-2026-0338

## Correction

- Cargo-resolved/checksummed `quinn-proto` **0.11.17 -> 0.11.18**.
- Cargo-resolved/checksummed `rustls` **0.23.43 -> 0.23.45**.
- Cargo also corrected two dependency edges in the supplied lock:
  `pwd-grp` -> `thiserror 1.0.69`, `tempfile` -> `getrandom 0.3.4`.
  Neither of those package versions was changed; the lock was generated by Cargo,
  not hand-edited or provided with invented checksums.
- Narrow version-floor checks run after upstream sync AND on the actual working
  crate before native compilation, so rollback cannot silently undo the fix.
  Patch resolution failure stops the build; newer versions are not downgraded.
- Native builds use `--locked` after the explicit security update. Successful
  builds save their actual Cargo.lock for audit, including the rollback path.
- cargo-audit is pinned to **0.22.2**. Audit JSON/status handling is robust to Bash
  errexit. CI's strict policy fails unresolved vulnerabilities and scanner failures,
  while displaying informational maintenance warnings and uploading the raw report.
- Existing scoped exception `RUSTSEC-2023-0071` (rsa Marvin timing attack) is
  preserved and explicitly displayed: this project's Tor use verifies RSA
  signatures, not attacker-controlled private-key decryption. The exception is
  not a claim that the dependency tree has zero advisories without exceptions.
- `bincode 2.0.1` / RUSTSEC-2025-0141 and `paste 1.0.15` / RUSTSEC-2024-0436
  remain visible unmaintained warnings. Replacing these transitive libraries
  requires upstream migration and is not disguised as an audit fix.

## Reproduce

Requires Python 3.11+, Rust/Cargo and network access:

```bash
python3 scripts/test-security-ci.py
python3 scripts/patch-engine-dependencies.py native/aether/aether
cargo install --locked cargo-audit --version 0.22.2
python3 scripts/audit-rust.py --strict --crate native/aether/aether \
  --report /tmp/aether-audit.json
bash scripts/test-core-sync.sh
sha256sum -c SOURCE_MANIFEST.sha256
```

The workflow additionally compiles all native backends, audits the captured build
lock, and runs the project's existing Android unit tests and release build.
