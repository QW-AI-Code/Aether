# اصلاح رابط، تب فعال و پرچم — Aether 1.6.0

## نسخه و محدوده

- `versionName = "1.6.0"`، `versionCode = 19` و `PATCHLEVEL = 1.6.0` دست‌نخورده‌اند.
- نگاشت قدیمی نسخهٔ APKهای تفکیک‌شده بر اساس ABI نیز تغییر نکرده است.
- موتور Rust، پروتکل‌ها، مسیرهای انتقال و کد اسکن شبکه تغییر نکرده‌اند. تغییرات مربوط به رابط، ذخیره‌سازی انتخاب کاربر، محدودسازی فهرست انتخاب و فرادادهٔ نمایشی‌اند.

## اصلاحات

### تب‌ها و ردیف سرور (a1)

- ضربدر و callback حذف از `ConfigTabStrip` حذف شدند. حذف همچنان از منوی مداد، با تأیید کاربر، انجام می‌شود.
- نشان شمارهٔ ردیف حداقل ۲۸×۲۸ dp دارد؛ رقم سفید خالص است. برای شماره‌های چندرقمی عرض می‌تواند به اندازهٔ متن افزایش یابد.
- عنوان فنی از آدرس واقعی `settings.vnext/servers` در outbound ساخته می‌شود؛ نام تبلیغاتی، لینک اشتراک، اطلاعات ورود، path، query، fragment و کنترل‌های نامرئی bidi به آن راه ندارند.
- قالب عنوان: `PROTOCOL S<ID> • host:port`؛ شناسهٔ پایدار سرور و حریم کانفیگ‌های قفل‌شده حفظ می‌شوند.
- دامنهٔ `workers.dev` و زیردامنه‌های آن در عنوان نشان داده نمی‌شوند. اگر تنها مقصد واقعی کانفیگ خودِ ورکر باشد، عنوان فقط پروتکل و شناسه را نشان می‌دهد: هیچ IP یا دامنهٔ جایگزین حدس زده نمی‌شود و SNI/WS Host به‌جای آدرس اتصال جا زده نمی‌شود. با وجود مقصد تمیز در outbound، یا پس از ثبت IP تمیز توسط اسکنر، آدرس تمیز و پورت نمایش داده می‌شوند. این تغییر صرفاً نمایشی است؛ آدرس واقعی اتصال دستکاری نمی‌شود.

### ماندگاری و انحصار تب

- `activeTab` داخل همان وضعیت رمزگذاری‌شدهٔ `CustomConfigStore` ذخیره می‌شود؛ خروج از صفحه یا بارگذاری مجدد انتخاب را ریست نمی‌کند.
- قالب ذخیره‌سازی به v4 ارتقا یافته و داده‌های قدیمی بدون این فیلد با انتخاب اولیهٔ «همه» بارگذاری می‌شوند.
- رابط، انتخاب اولیه، پایش و تلاش مجدد همگی از قاعدهٔ مشترک `ConfigCatalog.contains` استفاده می‌کنند؛ عضویت دیگر از سرور قبلی یا subscription آن استنتاج نمی‌شود.
- نتیجهٔ پینگ قدیمی پس از تغییر تب یا حذف سرور نمی‌تواند انتخابی خارج از محدوده ثبت کند (`selectInTab`).
- تب خودکار انتخاب‌شده حتی با صفر عضو باقی می‌ماند؛ تب خالی به «همه» یا موتور عادی fallback نمی‌کند. نبود سرور هنگام فعال بودن حالت سفارشی خطای قابل‌فهم می‌دهد.
- تنها حذف صریح خودِ تب انتخاب‌شده، انتخاب آن تب را به «همه» برمی‌گرداند؛ حذف تب دیگر و افزودن کانفیگ چنین اثری ندارند.

### چرخهٔ پیام اسکنر (a2)

- پیام‌های پایان، خطا، لغو، خالی و قفل‌شده پس از ۴ ثانیه منقضی می‌شوند؛ زمان‌بندی متعلق به manager است، نه عمر صفحه.
- کارت نتیجهٔ هر سرور نیز پس از ۴ ثانیه بسته می‌شود و امکان بستن دستی آن برقرار است.
- تغییر کانفیگ‌ها، تب فعال یا وضعیت اتصال پیام قبلی را نامعتبر می‌کند؛ نتایج مربوط به سرور حذف‌شده از صف پاک می‌شوند.
- شناسهٔ پیام مانع پاک شدن پیام جدید با تایمر قدیمی می‌شود. snapshot وضعیت نیز مانع پاک شدن پیام پایان جدید توسط مشاهده‌گر دیررسِ commit همان اسکن می‌شود.

### کشور و پرچم (a3)

- IP اولیه بدون انتظار برای کشور منتشر می‌شود. برای کشور نامشخص، دریافت تکمیلی با تلاش‌های محدود در پس‌زمینه ادامه می‌یابد.
- پاسخ سریع تکمیلی که قبل از انتشار اولیه برسد، به‌جای دور انداخته شدن منتظر انتشار همان IP می‌ماند.
- IP فاقد کشور که قبلاً توسط diagnostics منتشر شده نیز در مانیتور سرویس تکمیل می‌شود.
- traceهای HTTPS و استعلام صریح IP از `ipwho.is` به‌صورت موازی و از همان SOCKS تونل استفاده می‌شوند. استعلام صریح فقط IP خروجی نمایش‌داده‌شده را به سرویس مکان‌یابی می‌فرستد؛ مسیر مستقیمِ IP اپراتور تغییری نکرده است.
- کشور فقط برای همان IP و با کد معتبر ISO دوحرفی پذیرفته می‌شود؛ پاسخ نشست قبلی یا IP دیگر کنار گذاشته می‌شود. شکل‌های نوشتاری معادل IPv6 نیز تطبیق داده می‌شوند.
- پرچم یک فرادادهٔ اطلاع‌رسانی است؛ اختلاف دیتابیس‌ها، قطع سرویس یا نبود داده همچنان می‌تواند به نمایش کره منجر شود. کشور حدس زده نمی‌شود و نبود آن مانع اتصال نیست.

### دربارهٔ ما

- سازنده و توسعه‌دهندگان موتور Cluvex Studio در ابتدای بخش اعتبارات قرار گرفته‌اند.
- معرفی QW-AI-Code در بخش بعد، فقط به رابط، اسکنر، تب‌ها، نمایش Real Delay، فراداده و خوانایی/پیمایش رابط می‌پردازد؛ قابلیت‌های داخلی موتور به این بخش نسبت داده نشده‌اند.
- متن فارسی و انگلیسی هم‌زمان به‌روز شده‌اند.

## بازتولید تست و رندر

پیش‌نیاز: JDK 17، Android SDK با platform 35 و ابزارهای Gradle موردنیاز. برای release، کلید خصوصی واقعی خودتان را طبق `docs/SIGNING.md` از طریق متغیرهای محیطی یا `keystore.properties` فراهم کنید.

```sh
./gradlew testDebugUnitTest assembleRelease
```

در محیط کم‌حافظهٔ تحویل، محدودیت worker و heap از تنظیمات خارجی Gradle اعمال شد؛ تست‌ها حذف یا نادیده گرفته نشدند. اعتبارسنجی release با کلید موقتِ صرفاً آزمایشی خارج از سورس انجام شد؛ کلید، گذرواژه و APK آزمایشی در بستهٔ سورس قرار ندارند و آن کلید جایگزین کلید انتشار شما نیست.

برای تولید دوبارهٔ تصاویر در پوشه‌ای خارج از سورس:

```sh
AETHER_REPAIR_ARTIFACTS=/tmp/aether-ui-renders \
  ./gradlew testDebugUnitTest --tests '*UiRepairVisualTest'
python3 scripts/test-functional-wiring.py
```

تصاویر، رندر واقعی کامپوننت‌های تولیدی Compose با Robolectric و Native Skia و دادهٔ fixture هستند؛ اسکرین‌شات دستگاه واقعی، اتصال VPN زنده یا اثبات مکان جغرافیایی IP نیستند. نمونهٔ IP مستنداتی `192.0.2.1` و کشور `DE` صرفاً برای آزمون تغییر کره به پرچم استفاده شده‌اند.

این اعتبارسنجی شامل ساخت باینری‌های native با `scripts/build-natives.sh`، نصب روی دستگاه، استعلام زنده یا آزمون ترافیک سرتاسری VPN نیست. ورودی مرجع نیز فایل‌های `.so` نداشت؛ فرایند اصلی ساخت native/CI حفظ شده است. خروجی `assembleRelease` به‌تنهایی جای این آزمون‌ها را نمی‌گیرد.

## نتیجهٔ اجرای تحویل

نتیجهٔ نهایی، شمار تست‌ها و فهرست موارد اختیاری اجرا‌نشده در `validation/test-summary.json` و لاگ ساختِ ZIP جداگانهٔ رندرها ثبت می‌شود. تصاویر رندر و گزارش‌های اجرایی داخل سورس اصلی نیستند.

### نتیجهٔ تأییدشدهٔ این تحویل

- اجرای مشترک `testDebugUnitTest assembleRelease`: **BUILD SUCCESSFUL**، زمان اجرای ثبت‌شده ۶ دقیقه و ۱۸ ثانیه.
- JUnit: ۵۲۵ مورد، ۵۱۳ موفق، صفر شکست/خطا و ۱۲ مورد اختیاری skip‌شده (نمونه‌های خصوصی، هسته/اتصال زنده یا میزبان خاص دیالوگ‌های متنی).
- ۱۶ گارد آفلاین `scripts/test-functional-wiring.py`: موفق.
- ۲۰ تست جدید برای مدل/ذخیره‌سازی تب، پاک‌سازی عنوان، دریافت کشور، تحویل پاسخ زودرس، چرخهٔ پیام و رندر اضافه شده است؛ این تست‌ها در شمار بالا هستند.
- رندرها با کامپوننت تولیدی، Native Skia، محیط فارسی RTL و دادهٔ آزمایشی تهیه و از نظر بصری بازبینی شدند.
